# AprilTag Tracking — Hikrobot MV-CU013-A0GM

Тестовое приложение — основа будущего сервиса позиционирования погрузчиков SCADA System Route.
Получает кадры с промышленной камеры Hikrobot (MVS SDK), находит метки AprilTag, считает положение метки
относительно камеры и выдаёт измерения в JSON: в файл JSONL, по UDP, через callback и программный интерфейс.

Исходный скрипт сохранён без изменений: `legacy/apriltag_hikrobot_pose.py`.

## Что изменилось относительно исходного скрипта

| Проблема | Решение |
|---|---|
| `Error, more than one new minima found` от `pupil_apriltags` | `estimate_tag_pose` больше не вызывается. Положение считает OpenCV: `solvePnPGeneric(SOLVEPNP_IPPE_SQUARE)` + независимое решение `SOLVEPNP_SQPNP`, каждое уточняется `solvePnPRefineLM` |
| Данные только в терминале | Измерение — словарь JSON (схема `apriltag-measurement/1`): JSONL, UDP, `on_tag_detected` / `on_measurement` / `on_tag_lost`, `TrackingSession.latest()` |
| `image_test()` не передавал `pose_args` | Image Mode идёт через тот же конвейер, что и Live: положение считается (есть тест) |
| Нельзя оценить достоверность расстояния | `calibration.json` с флагом `calibrated`, проверка разрешения кадра, ошибка перепроецирования, статусы POSE_VALID / POSE_UNCERTAIN / NO_CALIBRATION, процедура проверки точности ([ACCURACY.md](ACCURACY.md)) |
| Нет журнала и оценки стабильности | JSONL с событиями `detected` / `update` / `lost`, сырые и сглаженные координаты, разброс за последние 30 кадров |

Подключение к камере взято из `open_hikrobot()` / `live_loop()` без изменения логики: поиск GigE по IP,
Continuous, Trigger Off, Exposure Auto Off, Mono8, Exposure 5000 мкс, `MV_CC_GetOneFrameTimeout` в свой буфер.
Добавлены обработка `MV_E_ACCESS_DENIED`, освобождение SDK при любом завершении и восстановление после таймаутов кадров.
Захват идёт в отдельном потоке, распознаванию отдаётся самый свежий кадр. Если обработка медленнее камеры,
промежуточные кадры пропускаются, а не копятся в буфере SDK — иначе положение отставало бы от реальности.
В панели и в итоге работы видны частота камеры, частота обработки и число пропущенных кадров.

## Установка (Windows, Python 3.13)

```bat
cd путь\к\apriltag_tracking
py -m venv .venv
.venv\Scripts\activate
py -m pip install -r requirements.txt
```

MVS SDK ставится вместе с MVS. Программа ищет `MvImport\MvCameraControl_class.py` там же, где исходный скрипт
(`C:\Program Files (x86)\MVS\Development\Samples\Python\MvImport`, папка `MvImport` рядом с `main.py`), либо в
папке из `--mvs-path`. **Перед запуском закройте MVS** — иначе камера занята (`MV_E_ACCESS_DENIED`).

## Запуск

| Режим | Команда |
|---|---|
| **Live** — только распознавание | `py main.py` |
| **Live** — с положением | `py main.py --calibration calibration.json --save-jsonl measurements.jsonl` |
| **Live** — как раньше, через `--fx/--fy` | `py main.py --tag-size-mm 100 --fx 997.28 --fy 997.28` (калибровка считается не подтверждённой) |
| **Image** | `py main.py --image apriltag_raw.png --calibration calibration.json` |
| **Video** (повторяемые тесты) | `py main.py --video test.avi --calibration calibration.json --no-window --save-jsonl out.jsonl` |
| **Calibration** — проверка файла | `py main.py --mode calibration --calibration calibration.json --image apriltag_raw.png` |
| **Calibration** — новая по доске | `py main.py --mode calibration --chessboard "calib\*.png" --square-mm 25 --tag-size-mm 100 --calibration-out calibration.json` |
| **Проверка точности** | `py main.py --calibration calibration.json --accuracy-cm 30,50,100 --accuracy-metric z` — см. [ACCURACY.md](ACCURACY.md) |

Клавиши в окне: **S** — сохранить исходный кадр и кадр с разметкой; **Q / Esc** — выход; **SPACE** — замер (режим точности).

## Статусы

| Статус | Значение | Координаты в метрах |
|---|---|---|
| `DETECTED` | метка распознана, расчёт положения выключен (`--no-pose`) | нет |
| `POSE_VALID` | положение вычислено и прошло все проверки | да, достоверные |
| `POSE_UNCERTAIN` | есть решение, но оно неоднозначно или недостаточно точно; причины — `status_codes` | да, **только для диагностики** |
| `NO_CALIBRATION` | нет параметров объектива или размера метки, либо калибровка для другого разрешения | нет, только пиксели |
| `LOST` | метки нет дольше `--lost-timeout-s` | нет — старые координаты не выдаются |

Коды причин `status_codes`: `ambiguous` (два решения PnP близки, а предыдущего положения нет),
`reprojection` (ошибка больше `--max-reproj-px`), `too_small` (сторона меньше 12 px), `steep_angle`
(метка под углом больше 75°), `uncalibrated` (`calibrated: false` или только `--fx/--fy`), `no_valid_solution`,
`jump_rejected` (скачок больше `--max-jump-m`), `jump_confirmed` (резкое перемещение подтверждено несколькими кадрами).

**Программам нужно доверять только `pose_valid == true`.**

## Как считается положение

* **Порядок углов.** `SOLVEPNP_IPPE_SQUARE` ждёт углы метки в порядке верх-лево, верх-право, низ-право, низ-лево
  (по часовой стрелке на изображении). `pupil-apriltags` отдаёт их против часовой стрелки, начиная с нижнего
  левого. Поэтому углы переставляются `[3, 2, 1, 0]`. Если после перестановки обход не по часовой стрелке (такое
  возможно только при ошибке в порядке), детекция отбрасывается, а не превращается в неверное положение.
  Первый угол на экране отмечен голубой точкой.
* **Два решения плоской задачи.** Для каждого решения проверяется: глубина Z центра и углов больше 0, к камере
  обращена лицевая сторона метки, ошибка перепроецирования. Если два решения близки по ошибке (отношение
  меньше `--ambiguity-ratio`), выбирается то, что ближе к предыдущему достоверному повороту этой же метки.
  Без истории — POSE_UNCERTAIN.
* **Почти фронтальная метка.** На идеально фронтальных углах OpenCV IPPE_SQUARE даёт верное смещение, но
  вырожденный поворот (ошибка около 4–6 px). Поэтому каждое решение уточняется методом Левенберга–Марквардта
  и добавляется решение SQPNP.
* **Системы координат.** Камера: X — вправо, Y — вниз, Z — вперёд по оси объектива. Метка: X — вправо, Y — вверх
  по рисунку, Z — из лицевой стороны.
  * `position_camera_m` — центр метки в системе **камеры**;
  * `camera_in_tag_m` — положение **камеры** в системе **метки**;
  * `rotation_tag_to_camera` — R, rvec, кватернион, углы Эйлера (только для чтения человеком);
  * `distance_m` = |t|.
* **Координаты погрузчика** (`forklift_pose`) всегда `null`: для них нужны мировые координаты меток и
  преобразование «камера → корпус». Их добавит сервис позиционирования Route.

## Сглаживание и сопровождение

* Сырые (`position_camera_m`) и сглаженные (`smoothed.position_camera_m`) координаты выдаются раздельно.
* X, Y, Z сглаживаются экспоненциально, только по достоверным измерениям. Ориентация сглаживается интерполяцией
  кватернионов, поэтому на границе ±180° скачков нет.
* Скачок больше `--max-jump-m` отбрасывается. Но если 3 кадра подряд согласованно показывают новое место, метку
  действительно переместили: фильтр переходит к новому положению, реальное движение не прячется.
* После потери метки сглаживание начинается заново: пока метку не было видно, её могли переставить.
* `stability` — разброс по X, Y, Z и по расстоянию за последние 30 достоверных кадров.
* Событие `detected` выдаётся один раз при появлении метки, а не на каждом кадре. Дальше идут `update`,
  при пропадании — `lost`. Если кадры перестали приходить (таймаут камеры), метки всё равно переходят в
  `LOST` по времени.

## Измерения для других программ

Пример измерения из `examples/measurements.example.jsonl`. Он получен настоящим прогоном программы по
**синтетическому** видео (кадры с метками в известной позе), а не снят с вашей камеры:

```json
{"schema":"apriltag-measurement/1","event":"update","camera_id":"video:synthetic_test.avi","camera_ip":null,
 "timestamp":"…Z","frame_id":2,"family":"tag16h5","tag_id":3,"status":"POSE_VALID","status_codes":[],
 "pose_valid":true,"calibration_valid":true,"center_px":[…],"corners_px":[…],"hamming":0,"decision_margin":null,
 "position_camera_m":{"x":…,"y":…,"z":…},"distance_m":…,"rotation_tag_to_camera":{"rvec":[…],"matrix":[…],
 "quaternion_wxyz":[…],"euler_xyz_deg":[…],"tilt_deg":…},"camera_in_tag_m":{…},"reprojection_error_px":…,
 "pnp":{"solutions":…,"ambiguity_ratio":…,"resolved_by_prior":false,"alternative":…},
 "smoothed":{"position_camera_m":{…},"distance_m":…},"stability":{…},"forklift_pose":null,…}
```

С камерой и `pupil-apriltags` поле `decision_margin` заполнено. В примере оно `null`, потому что пример
построен запасным детектором OpenCV.

Способы получения (подробно — `examples/consumer_example.py`):

```python
from apriltag_tracking import TrackingSession

s = TrackingSession.from_cli(["--ip", "169.254.19.203", "--calibration", "calibration.json"])

@s.hub.on_tag_detected
def on_tag_detected(m):  # появление метки
    print(m["tag_id"], m["status"])

s.start()                       # захват и распознавание в фоновом потоке, без окна
m = s.latest("tag16h5:3")       # последнее измерение или None
s.stop()                        # остановка, камера освобождается
```

* **JSONL** — `--save-jsonl`; чтение из другой программы — `latest_from_jsonl(path)` / `read_jsonl(path)`.
* **UDP** — `--udp 127.0.0.1:5005`: одна датаграмма JSON на измерение. Этот же словарь годится для WebSocket.
* Запись и callback выполняются в отдельном потоке через ограниченную очередь. Медленный потребитель не
  тормозит захват; лишние измерения отбрасываются, счётчик выводится при завершении.

## Калибровка

`calibration.example.json` — **только пример формата**, с номинальными параметрами (`calibrated: false`).
Настоящую калибровку можно сделать прямо этой программой.

**Проще всего — съёмка с подсказками:**
`py main.py --mode calib-capture --board 9x6 --square-mm 25 --tag-size-mm 100 --exposure-us 2000`.
В окне сразу видно, найдена ли доска (цветные углы) или нет (красная надпись); пересвеченные места
подкрашены красным. Держите доску неподвижно — снимок сохранится сам, если такого положения ещё не было
(папка `calib\<дата_время>`). Сетка 3×3 показывает, где доска уже снята; подсказка `next:` — куда поставить
дальше. SPACE — сохранить принудительно, Q — закончить. После 20 снимков (`--calib-frames`) калибровка
выполняется автоматически и пишется в `calibration.json`.

Вручную, по уже снятым кадрам:

1. Распечатайте шахматную доску (например, 10×7 клеток → 9×6 внутренних углов), наклейте на жёсткое основание,
   измерьте клетку.
2. Снимите 15–25 кадров (клавиша **S** в Live Mode) при 1280×1024: доска в разных частях кадра, особенно в углах,
   с наклонами до 30–40°, без смаза.
3. `py main.py --mode calibration --chessboard "calib\apriltag_raw_*.png" --square-mm 25 --tag-size-mm 100`
   — число углов доски определится само (`--board auto`; можно задать явно, например `--board 9x6` —
   это ВНУТРЕННИЕ углы, а не клетки). По каждому снимку печатается «OK» или «НЕ найдена» с причиной,
   а в папке `calib_debug` сохраняются снимки с отмеченными углами. Запишется `calibration.json`
   с `"calibrated": true`. Нормальный RMS — до 0,5 px; больше 0,8 px — переснять.
   Снимки с одной лишь меткой AprilTag для калибровки не подходят: нужна шахматная доска целиком в кадре.
4. `py main.py --mode calibration --calibration calibration.json --image apriltag_raw.png` покажет параметры,
   углы метки и оба решения PnP для контрольного снимка.

Калибровка верна только для этой камеры, объектива, фокуса и разрешения. При другом разрешении кадра метры
отключаются (статус NO_CALIBRATION). Если меток разного размера несколько, задайте `"tag_sizes_mm": {"tag16h5:3": 100}`.

## Тесты

```bat
py -m pytest -q
```

Тесты работают без камеры, на синтетических кадрах с меткой в точно известной позе и на имитации MVS SDK:

* распознавание ID 3 и нескольких меток сразу, отсутствие ложных меток на шуме, шахматке и тексте;
* фильтры hamming и margin, повторяющийся ID;
* порядок углов для PnP (pupil → IPPE, отбраковка зеркального порядка);
* расстояние: точное на идеальных углах, ошибка меньше 1 % на сгенерированных кадрах 0,3–1,5 м;
* два решения PnP: выбор по ошибке, разрешение неоднозначности по предыдущему повороту;
* отбраковка решений позади камеры и большой ошибки перепроецирования, учёт дисторсии;
* события `detected` / `update` / `lost`, потеря без кадров, восстановление, сглаживание и отсев скачков,
  поворот через ±180°;
* корректный JSON, JSONL, callback, UDP, неблокирующая выдача, `TrackingSession`;
* режимы Image (с положением), Video (потеря и восстановление), Calibration (проверка файла и калибровка по
  доске), проверка точности;
* MVS: выбор камеры по IP, `MV_E_ACCESS_DENIED`, освобождение SDK при ошибке, таймауты и перезапуск захвата.

Тест порядка углов `pupil-apriltags` на реальных кадрах запускается только при установленном пакете. Сначала
запустите тесты у себя — этот тест должен пройти.

## Что проверено, а что нет

* **Проверено:** вся логика и геометрия на синтетических кадрах, подключение к MVS на имитации SDK.
  Ошибки `more than one new minima found` не может быть, потому что эта функция `pupil-apriltags` не вызывается.
* **Не проверено:** реальная камера MV-CU013-A0GM (в среде разработки камеры не было) и `pupil-apriltags`
  (пакет в среде разработки не устанавливался — тесты шли на запасном детекторе OpenCV). Первый запуск на
  оборудовании:
  1. `py -m pytest -q` — должно пройти всё, включая тест `pupil`.
  2. `py main.py` без калибровки: метка ID 3 с зелёным контуром, `DETECTED` в консоли один раз, margin около 25–27.
  3. Калибровка, затем замер на 30 / 50 / 100 см по [ACCURACY.md](ACCURACY.md).
