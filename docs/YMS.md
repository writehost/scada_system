# YMS — территория завода

Модуль двора внутри существующего WMS. Отдельного backend и отдельного входа нет.

Адрес после деплоя: `https://wms.scada25.ru/yms`, КПП: `https://wms.scada25.ru/yms/gate`.

API: `/api/wms/yms/*`. Авторизация — та же сессия Scada ID, площадка `siteCode` как у остального WMS.

## Что делает MVP

- Заявка на визит и справочник машин (не путать с карщиками склада ГП).
- Очередь со строгой сменой статусов.
- Доки и стоянки, атомарное назначение, один визит на док.
- Диспетчерская: очередь, план, доки, журнал.
- КПП: поиск по номеру, въезд, выезд, внеплановый визит.
- Связь с заказом отгрузки или отбора WMS только чтением. Остатки YMS не пишет.
- Исходящую погрузку нельзя закрыть, пока склад не подтвердил количество, либо явно зафиксировано расхождение.

## Чего нет в этом срезе

Календарь окон, портал водителя, WebSocket (в проекте его нет — диспетчерская обновляется опросом), SMS, распознавание номеров, шлагбаумы, кросс-док как складской процесс.

## База

Таблицы `yms_*` создаются при первом запросе к API (`CREATE TABLE IF NOT EXISTS`). Это добавление таблиц, не правка остатков.

На боевой базе так делать только после подтверждения. До деплоя код можно смотреть локально. Повторный запрос схему не ломает.

Стартовый план (D-01…D-04, P-01…P-06, КПП) появляется один раз, если у площадки ещё нет объектов. Его двигают в режиме «Править план».

## Роли

Существующие: `admin` и `warehouse_manager` — полный доступ, `warehouse_operator` — чтение и подтверждение расхождения, `auditor` — чтение.

Дополнительно, если строки есть в `wms_roles`: `yms_dispatcher`, `yms_guard`, `yms_logist`, `yms_warehouse`. Модуль пытается добавить эти коды, если в `wms_roles` есть колонки `code` и `name`.

## Локально

```bash
npm run test:yms
npm run dev
```

Нужны `DATABASE_URL` или `wms-config.json`, как у остального WMS. Без базы API ответит 503, страницы покажут ошибку связи.

В development пустой `WMS_BACKEND_URL` проксирует `/api/wms` на `:3001`. Чтобы маршруты YMS из этого приложения отвечали сами, запускайте с `WMS_DISABLE_DEV_PROXY=1`. На заводе `WMS_BACKEND_URL` пустой и прокси выключен — там это не нужно.

## Деплой на завод

Не запускать, пока не подтверждена миграция.

1. Скопировать изменённые файлы в `/opt/scadatable-wms/current/Frontend` без `src/`.
2. `swapon /swapfile`
3. Остановить только `scadatable-wms-ui`, собрать от пользователя `scadatable`:

```bash
systemctl stop scadatable-wms-ui
cd /opt/scadatable-wms/current/Frontend
rm -rf .next/cache
sudo -u scadatable env NODE_ENV=production \
  NODE_OPTIONS=--max-old-space-size=1400 \
  /usr/bin/npx next build --webpack
systemctl start scadatable-wms-ui
```

4. Открыть `/yms` под пользователем с ролью склада. Первый запрос создаст таблицы в `wms_edge`.
5. Векас, туннели и `scadatable-wms-api` не трогать.
